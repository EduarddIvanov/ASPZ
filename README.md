# ASPZ

## Опис

Програма zd6var.c реалізує інструмент для моніторингу та детального логування краху процесів. Використовуючи системний виклик `ptrace`, програма збирає розширену інформацію про стан процесу в момент аварійного завершення, включаючи стан регістрів, дамп стеку та іншу діагностичну інформацію.

## Функціональність

- **Моніторинг процесів**: Підключення до існуючих процесів через PTRACE_ATTACH
- **Детекція краху**: Відстеження критичних сигналів (SIGSEGV, SIGBUS, SIGFPE, SIGILL, SIGABRT)
- **Збір діагностики**: Читання регістрів процесора та дампу пам'яті
- **Детальне логування**: Запис структурованої інформації про крах у лог-файл
- **Тестовий режим**: Вбудована можливість створення тестового краху

## Компіляція

```bash
gcc -o enhanced_logger zd6var.c
```

## Використання

### Моніторинг існуючого процесу
```bash
sudo ./enhanced_logger <PID>
```

### Тестовий режим
```bash
sudo ./enhanced_logger test
```

## Що логується

Програма записує у `/var/log/enhanced_crash.log` наступну інформацію:

- **Базова інформація**: Час краху, PID процесу, тип сигналу
- **Стан регістрів**: RIP, RSP, RBP, RAX, RBX, RCX, RDX
- **Дамп пам'яті**: Hex-представлення стеку (перші 256 байт)
- **Контекст**: Детальний опис умов краху

**Обробка стандартних сигналів (SIGINT, SIGTERM)**
Було створено програми для перехоплення сигналів `SIGINT` (Ctrl+C) та `SIGTERM` з використанням функції `signal()`. При отриманні `SIGINT` програма продовжувала роботу з виведенням повідомлення, тоді як `SIGTERM` призводив до коректного завершення через `_exit()`. Реалізація включала виведення PID для можливості надсилання сигналів з інших терміналів. Це дослідження розкрило основи роботи обробників сигналів та їхню асинхронну природу.

**Контроль доставки сигналів (sigprocmask)**
Створено демонстрацію блокування сигналу `SIGINT` за допомогою `sigprocmask()`. Показано механізм тимчасового блокування сигналів з подальшою обробкою після розблокування. Такий підхід забезпечує захист критичних секцій коду від небажаних переривань. Вивчено роботу з типом `sigset_t` та функціями `sigemptyset()`, `sigaddset()`.

**Управління життєвим циклом процесів (SIGCHLD + SA_NOCLDWAIT)**
Реалізовано рішення для попередження створення зомбі-процесів через `sigaction()` з прапором `SA_NOCLDWAIT` та обробником `SIG_IGN`. Програма створювала дочірні процеси через `fork()` та забезпечувала відсутність залишкових записів у таблиці процесів після їх завершення. Це завдання поглибило розуміння взаємодії між батьківським та дочірніми процесами через механізм `SIGCHLD`.

**Діагностика помилок пам'яті (SIGSEGV і siginfo_t)**
Створено обробник для `SIGSEGV` з доступом до структури `siginfo_t`. Реалізовано виведення адреси порушення доступу через поле `si_addr`. Це продемонструвало можливості отримання детальної діагностичної інформації під час аварійного завершення процесів.

**Аналіз машинного стану (ucontext_t)**
В обробнику `SIGSEGV` отримано доступ до `ucontext_t` для зчитування регістра `RIP` на архітектурі x86_64. Це показало можливості низькорівневого аналізу стану процесу під час краху з доступом до повного контексту виконання.

**Переривання системних викликів (nanosleep)**
Програма використовує `nanosleep()` в циклі з перевіркою `errno == EINTR`, що забезпечує коректне відновлення паузи після отримання сигналу. Це демонструє правильну обробку переривань системних викликів.

**Міжпроцесна взаємодія через сигнали (subscriber + publisher)**
Реалізовано взаємодію між процесами за допомогою `SIGRTMIN`. Підписник встановлює обробник через `sigaction` з `SA_SIGINFO` та виводить параметри сигналу включно з PID відправника та переданим значенням. Видавець використовує `sigqueue` для передачі значення `42`. Це показує можливість передачі даних разом із сигналами реального часу. Сигнали `SIGRTMIN` підтримують чергування, що запобігає втратам при інтенсивному обміні. Такий механізм є альтернативою сокетам чи каналам для простого IPC.

**Синхронна обробка сигналів (sigwaitinfo)**
Створено приклад блокування сигналів `SIGUSR1` і `SIGUSR2` з виведенням відкладених сигналів через `sigpending()` та синхронним очікуванням через `sigwaitinfo()`. Це продемонструвало ситуацію доставки але не обробки сигналу через маскування, де `sigwaitinfo()` дозволяє синхронне перехоплення. Показано альтернативний підхід до обробки сигналів без асинхронних обробників.

## Безпека

- Програма потребує підвищених прав для роботи з ptrace
- Логи записуються в захищену системну директорію

## Висновок

Цей інструмент призначений для діагностики та налагодження. Використання ptrace може вплинути на продуктивність моніторованих процесів. Призначений для дослідницьких цілей та специфічних випадків налагодження системних проблем.
